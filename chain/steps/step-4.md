# Step 4: Voice controller, keyboard (IME), RecognitionService

Deliverables:
- `VoiceController` (process-wide singleton, main-thread state via StateFlow or listener list): states IDLE, RECORDING, TRANSCRIBING, ERROR(message). `toggle()`, `start()`, `stopAndTranscribe()`, `cancel()`. Uses WavRecorder then the Transcriber from step 3 on a coroutine/executor, then publishes `Result(text)` to an `OutputSink` (always deliver on the main thread; `commitText` must run on the main looper). Guard against double taps (ignore toggles while TRANSCRIBING). Auto-recover from stale state. Plain Kotlin where possible so it unit-tests without Android (inject recorder/transcriber/sink interfaces); write unit tests with fakes for: toggle cycle, too-short recording, transcription error, double toggle.
- `DexVoiceIme : InputMethodService` registered in the manifest with `android.permission.BIND_INPUT_METHOD`, `res/xml/method.xml` (subtype voice-first; settings activity). Input view is a simple, large, high-contrast layout: big mic button (state colors and label: "Tap to talk", "Listening… tap to stop", "Transcribing…", error text), backspace (hold repeats), space, enter (use `performEditorAction` or key event as appropriate), globe (`switchToNextInputMethod`), gear (opens SettingsActivity). Override `onEvaluateInputViewShown()` to return true when the setting "always show on-screen keyboard" is on (so it still shows with a hardware keyboard attached). Keep the active IME instance in a static weak reference so the controller's `OutputSink` can `currentInputConnection.commitText(text, 1)`. If there is no active input connection, copy to the clipboard and show a toast "Copied, paste with Ctrl+V". If `currentInputEditorInfo.inputType` is a password field, still insert but never log the text.
- `DexVoiceRecognitionService : RecognitionService` plus `res/xml/recognition_service.xml` (`<recognition-service android:settingsActivity=...>`), declared in the manifest with `android.permission.BIND_RECOGNITION_SERVICE` and the `android.speech.RecognitionService` intent filter. Implement `onStartListening` (record with WavRecorder until `onStopListening` or silence/timeout), transcribe, and report via `Callback.results` with `SpeechRecognizer.RESULTS_RECOGNITION`; map failures to `SpeechRecognizer.ERROR_*` codes; implement `onCancel`. This is what makes the app appear under Settings > Voice input. Foreground-service rules: recording from a background service on Android 14 needs microphone foreground-service type; use a short-lived foreground notification if required.
- Manifest entries for both services; mic permission requested from SettingsActivity (not from the service).
- Unit tests for VoiceController.

Done when: compiles, manifest components are valid (permission/exported/intent-filter attributes correct for API 34), controller tests written and (if a local SDK exists) green.
